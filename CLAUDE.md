# lava

Vulkan abstraction in Rust (stable, edition 2024) with bindless resources, automatic barrier tracking and typed pass bindings generated from Slang at build time. Its main user is the game engine in `../GameEngine` (`core` depends on `lava` and `lava-build-slang` by path); its docs show how the engine uses lava where that explains a design.

## Orientation: read this before exploring
- A **code map** (each file's purpose, key types, plus live git state) is injected at session start by a `SessionStart` hook, which runs the engine's `tools` generator (`../GameEngine/tools`) with `--root .`. Check it before running `ls`/`rg`.
- Full pub signatures and struct fields live in `.claude/context/api/{lava,lava-build-slang,lava-tests,lava-macros}.md` (`lava-tests.md` also lists the generated test pass bindings, from the newest debug build). Read the relevant file instead of grepping for an API.
- To refresh them by hand: `cargo run -q --release --manifest-path ../GameEngine/tools/Cargo.toml --target-dir ../GameEngine/target/tools -- --root .` (stable cargo, cached by mtime). The engine's own sessions map lava too (`--with ../lava`).
- **Subagents don't get the hook output.** When delegating exploration, tell the subagent to read `.claude/context/codemap.md` first.
- Known bugs, intended limitations and ideas for future work are listed in `STATE.md`; the publishing review is `lava/SURVEY.md`. Check them before debugging or designing, delete an entry when you fix or build it, and add bugs you find but don't fix and ideas worth keeping.
- Every `.rs` file starts with a one-line `//!` doc that feeds the code map. Keep it accurate when a module's role changes, and add one to every new file.

## Crates (dependency order)
- `lava-macros`: proc macros for lava (validation tracing).
- `lava-build-slang`: lava's Slang frontend, called from an application's `build.rs` (see Shader pipeline); compiles its Slang passes and generates their bindings and `PASS_MAP`. Its `slang/` (searched by every session) holds `bindless.slang` and `ray_tracing.slang`, the Slang side of lava's shader contract (the "Shader contract" section of lava's `lib.rs` docs: the set and binding declarations lava maps to its descriptor heaps, push data, handle, sampler and instance layouts), and `profile.slang`, shader clock helpers lava has no part in, whose readout it generates (see Shader clock regions). With its `hot-reload` feature (only as a normal dependency; the build script's copy never compiles lava) it also holds the runtime shader hot reload. The only crate that links Slang; lava has no Slang in any feature combination, so a frontend for another language (`lava-build-glsl`, see STATE.md) could sit beside it.
- `lava`: Vulkan abstraction over `ash` + `gpu-allocator`; it takes SPIR-V and has no Slang. Global `Ctx` state, bindless descriptors in two `VK_EXT_descriptor_heap` heaps, which shaders index directly (`ImageHandle<K>`, and runtime `Sampler`s; lava allocates the slots, see Bindless slots), `lava::init(&Config { display, validation, disabled, pipeline_cache, ..Config::new(&PASS_MAP) })` (`display: None` = headless; the application's pass map, see Shader pipeline; `app_name`/`app_version` for `VkApplicationInfo`; `validation` in any build, a warning and no validation without the layer installed; the optional features lava leaves off even where the device has them, for tests; an optional `&'static Path` of the `VkPipelineCache` data, see Pipelines; `memory_blocks`, the allocator's block sizes (`memory_report()` reads its live bytes, counted at every allocation and free, `ALLOCATED`, and its blocks' capacity, plus the cached heaps and the budget); there are no init-time samplers; see Lifecycle and errors). Device features live in `features.rs` (see Optional features): lava tries the GPUs by type (`state::device_order`: discrete, integrated, then virtual and CPU ones such as lavapipe, with a warning) and picks the first with everything lava itself needs (Vulkan 1.4, `FeatureChain::lava_missing`: descriptor heaps with 256 bytes of push data, untyped pointers (`VK_KHR_shader_untyped_pointers`, which heap-indexing SPIR-V declares; Within a rendering, depth and blending follow draw order without barriers, but nothing else does, so `record` panics when a draw accesses what another draw of it writes (attachments aside, and pairs of `BufferAccess::unordered()` accesses: atomics or disjoint writes whose order the application guarantees doesn't matter). Attachments are views of one mip, covering the render area. `RasterBuilder<'a, N>` has the attachment count in its type, and so does a `Draw<'a, N, E>` (`E`: its index or indirect buffers), so a draw with the wrong number of blends doesn't compile; a `Draw` derefs to the unsized `DrawOutput` (blends, write masks and those buffers as sections, like `BindingOutput`), which the builder borrows: its methods take and return `&mut Self`, the first 16 draws are kept inline (a `SmallVec` of pointers in the builder, tied to `'a` by a `PhantomData<&'a DrawOutput<'a>>`, so draws can be temporaries of the recording statement, dropped before the builder made first: a `SmallVec` of references would need them alive at its `Drop`, and `#[may_dangle]` is nightly-only), and draws added in a loop are built before the rendering. Direct draws of 0 instances are skipped. Raster passes without a fragment entry point (`PassKind::RasterVertex`/`RasterMesh` with `fragment: None`) draw depth and stencil alone. Dynamic rendering local read isn't supported (STATE.md).
- Unsized types with sized builders (`Bindings`/`BindingOutput`, `Draw`/`DrawOutput`) are declared with the crate-internal `unsized_struct!` (`lava/src/unsized_struct.rs`): fixed fields, then each section's offset and length (stored by `from_parts`, so accessors don't walk earlier sections), then `[T; L]` sections (aligned to at most 8, a `const` every accessor evaluates) that the unsized struct reads back as slices. Use it for any new one. A `RasterBuilder`'s draws are a `DrawList<'a>` whose `iter()` lends them for the list's borrow only.
- Traits only lava implements (`Format`, `ImageUsage`, `BufferUsage`, `Dim`, `Views`, the aspect markers, the image kinds of `image/kind.rs`, `QueueKind` with `HasCompute`/`HasGraphics`, the query kinds, `Level`, `IndexFormat`, `VertexPosition`) have the supertrait `crate::sealed::Sealed`, a public trait in a private module: other crates can bound by them but not implement them, and their sub-traits (`IsSampled`, `HasTexels`, ...) are sealed through them. Seal new ones the same way. `Describe`/`Described` (what a build reads of its geometry) are public items of a private module, so `Level::Geometry` can name them while nothing outside lava does.
- Submission and presenting (`queue/`, `present.rs`): a `Timeline<K>` (`Timeline::new(in_flight, staging)?`, the staging ring size in bytes, see uploads; `K` is `queue::Graphics`, or `Compute`/`Transfer`, which need `async-compute`/`async-transfer` and return `MissingFeature` without a dedicated family; at most `MAX_TIMELINES` = 8, else `Error::OutOfTimelines`) owns one of 8 timeline semaphores (`queue/timeline.rs`, `INDICES`, kept for lava's lifetime, so values go on and old `Wait`s stay valid when another timeline gets the index), pinned to the least shared queue of its family (`DeviceQueues`/`FamilyQueues` in `queue/mod.rs`: graphics plus the dedicated compute and transfer families, at most 8 queues each, a `Mutex<vk::Queue>` per queue and one `Mutex` of per-queue timeline counts per family; `Ctx::queue_family(Kind)`/`queue_count(Kind)`), with `in_flight` command pools. Each index counts the value its last submission signalled (`Index::submitted`; a submission signals the next) and the value of the recording in progress (`Index::recording`). `timeline.begin()?` borrows the timeline mutably (`Submission<'_, K>`, so one at a time, without a runtime check; core's `render()` holds its `FrameTimeline` through `world.resource_scope`), waits for the frame slot's last submission and releases what completed submissions kept (see Lifetimes); `submission.slot()` cycles through the slots for per-frame rings and query pools; `submission.wait_for(other.at(GraphicsStage::Raster))` adds waits at a stage of the waiting family's set (`Wait<S: StageSet = AllStages>`; `QueueKind::Stage` is `GraphicsStage`, `ComputeStage` or `TransferStage`, and `wait_for` takes a `Wait<S: StageOf<K>>`: `AllStages`, its own set, transfer stages everywhere, compute stages on graphics, so a raster stage on a compute submission doesn't compile; ray tracing stages are masked to the indirect reads without ray tracing pipelines; one on its own timeline is dropped, two on one timeline keep the later value at both stages); `submission.submit(|cmd: &mut CommandBuffer<K>| ..)? -> Wait` signals the next value (`wait.block()`/`block_timeout(d) -> bool`/`is_done()`, `Wait::all(&[..])`/`all_timeout`, one `vkWaitSemaphores`, then a release). A value no submission will signal is signalled from the host (`host_signal`, after the index's earlier submissions): a failed recording whose barrier-only replay failed too; device loss leaves the values alone. Polls and waits return `Result`, so `Error::DeviceLost` comes out of `begin`, `submit`, `block`, `wait_idle` (logged once, `Ctx::device_lost`). `submit` records with the timeline's every-structure accesses borrowed (`Recording<'p>`, `CommandBuffer<'p, K>`), the closure (uploads only where it calls `cmd.drain_uploads`), ends every submission with a barrier that makes its writes host-visible (readbacks, clock counters), and submits with the waits and signals; a recording that never reaches the GPU (its closure panicked, or recording or submitting failed) is replaced by a submission of just the barriers it computed (`Recording::barrier_log`) with the same waits, signalling the value, so the tracked image states stay true, its drained uploads are published again, and the panic continues (a submission that used an acquired swapchain image without presenting it, or whose recording left a query active, panics with that message after the replay). `CommandBuffer<K>` wraps the untyped `Recording`: renderings, blits and presents need `K: HasGraphics`; dispatches, traces, acceleration structure commands and image clears `K: HasCompute`; copies, fills, updates, timestamps, scopes and `flush_all` work on every kind, and queries of the kinds its family records (`query::RecordedOn<K>`, see Queries) (a transfer family binds no descriptors; its image copies need 4-byte aligned buffer addresses and boxes within its `minImageTransferGranularity`, in blocks for compressed formats, and copies of depth or stencil images, either way, need graphics). Images are `EXCLUSIVE` to one family at a time, tracked as the owner in their state: an access by another family panics unless the owner recorded `cmd.release::<D>(view)` (or `cmd.drain_uploads` of an `uploader_for::<D>()`'s copies released it), and the receiver's first access records the acquire half in a barrier call of its own (`Barriers.acquires`); both halves are one barrier per tracked state (`ownership_ranges`: all mips of a `Single` image, each mip of a `MipChain`), so they name the same subresources whatever mips each side accesses together. The receiving submission must `wait_for` the releasing one, which lava doesn't check. The image's states are the image's (one, or one per mip indexed by mip level, also in a mip view), so a release forgets the image's pending accesses only once the family owns none of its mips (`released_by`). Buffers are `CONCURRENT` between every family lava created queues of. Host image copies (`Image::copy_from`) aren't synchronised with submissions in flight. `PresentSurface<U>` (`present.rs`) owns a window's surface, its swapchain (made by the first `acquire`, recreated there on a new size, present mode or composite alpha or a suboptimal or out-of-date result, up to three tries; the old one moves to the surface's retired list before the new one is created, so a failed creation leaves none and the next starts with a null `oldSwapchain`; a retired one goes once its present fences signalled and nothing in flight uses it, `destroy_when_idle`), the semaphores and present fences between them, and one current image. `new(display, window, &[SurfaceFormat])` needs `present-fences` (`MissingFeature` without it) and picks the first preferred `SurfaceFormat { format: format::Dynamic, color_space: ColorSpace }` the surface has whose format supports `U`, else another one lava has a type for, logged, with `is_preferred_format()` false (`surface_format()`, `format()`, `color_space()`); colour spaces besides sRGB, HDR10 among them, come from `VK_EXT_swapchain_colorspace`, which init enables with a display where the instance has it. `PresentMode` is an enum (`Fifo`, `FifoRelaxed`, `Mailbox`, `Immediate`, and `FifoLatestReady` with `fifo-latest-ready`): `present_modes()`, `supports(mode)`, `set_present_mode(mode) -> bool`; `set_composite_alpha(CompositeAlpha) -> bool` (default: the first of `CompositeAlpha::ALL` the surface supports); `set_hdr_metadata(&HdrMetadata)` (`hdr-metadata`) applies to the swapchain and every later one. Surface capabilities are cached per requested size and queried again on a new size, a suboptimal or out-of-date result and after a recreation. `surface.acquire(window_size)? -> bool` makes an image current (`false` at zero size or minimised) with its state reset to `UNDEFINED` (its contents are discarded), `surface.current_image()` is its view for the submission, which ends with `cmd.present(&mut surface)` (the image's last command in the recording: a later access panics; panics if a submission presented it already; it marks the image presented last, after its barrier), then `surface.present()?` or `present::present_all(&mut [&mut a, &mut b])?` (one `vkQueuePresentKHR` for several surfaces, of any usage) presents it on graphics queue 0. `acquire`, `present` and `present_all` panic on a thread that is recording (`timeline::RECORDING`): call them before or after `submit`. `present` takes its fence (a free one reset, or a new one) before the image stops being current. An image no submission presented stays current: `present()` leaves it, the next `acquire` returns it again, at its size, with its tracked state reset (only a failed recording can have touched it), so a resize takes effect a frame later; an `acquire` after a presenting submission without `present()` presents first. Only dropping the surface with a current image waits for an empty submission that consumes the semaphore it left signalled. The presenting submission must be the one that first uses the image (else it panics): it waits for the acquire at the stage of that first access (the image state's `acquired` flag) and signals the image's own present semaphore, and `cmd.present` writes the recording's timeline and value into the surface's current image while recording, before anything is submitted. A replaced swapchain waits in the surface until its present fences signalled, then goes once nothing in flight uses it (`destroy_when_idle`); dropping the surface waits up to 1 s for its present fences, then hands everything to `destroy_when_idle`. Swapchain images are bound in every bindless set their usage allows and owned by graphics.
- Lifetimes (`object.rs`, `queue/timeline.rs`): every lava object (buffer, image, acceleration structure, sampler, query pool) lives in an `Arc` of its internal, which its handle (unique, not `Clone`), the referencing buffers that hold it (see Referencing buffers) and the submissions that use it share; views, slices and `Wait`s are `Copy` and borrow or name what they use. A recording keeps every object its commands track and every query pool it uses (`Keep`, once each by the recording's tag in the object's `Header::last_kept`), and its submission moves them into its index's kept list at its value (`timeline::keep_until`); `begin`, the waits of a `Wait`, `lava::reclaim()` (polls), `lava::wait_idle` and a timeline's drop release what completed submissions kept, outside the lock. Every `Drop` destroys right away, on whatever thread lets go last, also while recording: nothing a recording holds a lock on is touched by a destructor. What no recording tracks waits for every recording in progress and submission in flight (`keep_until_idle`/`destroy_when_idle`, by `Index::recording` and `Index::submitted`): a reloaded pass's pipelines, a dropped sampler's slot (push constants name samplers without keeping them), unbound sparse pages, retired swapchains and a dropped surface's, and what `host_write_referencing` replaced. `lava::shutdown` waits for the device and releases everything kept before it counts live objects.
- Ray tracing (`vkobjects/acceleration_structure.rs`, `vkobjects/compactor.rs`, `vkobjects/rt_pipeline.rs`): five features, `acceleration-structure`, and `ray-query`, `ray-tracing-pipeline` and `ray-tracing-position-fetch` (`VK_KHR_ray_tracing_position_fetch`: `BuildFlags::allow_data_access`, `HitTriangleVertexPosition`) on top of it, `ray-tracing-invocation-reorder` (`VK_EXT_ray_tracing_invocation_reorder`, Slang's `HitObject`/`ReorderThread`, `ShaderInvocationReorderEXT`; the struct and name are in `vk.rs`) on top of pipelines (the modules and commands are `#[cfg]`'d by them; creations return `MissingFeature` where checked, and a pass whose SPIR-V declares their capabilities has `Gated` bindings, like any pass whose capabilities need a feature). `Blas`/`Tlas` (`AccelerationStructure<Bottom/Top>`) live in their own memory or a range of a `StructureArena` (one buffer, first-fit 256-byte units from bindless's `Ranges`, given back by the structure's destructor; structures hold an `Arc` of it, so the arena can drop first; `arena.blas/blas_with_capacity/tlas/compacted/clone_target/deserialized`), are created by `vkCreateAccelerationStructure2KHR` from an address range, and know their device address (not their buffer's), scratch sizes (multiples of `scratch_alignment()`) and the shapes they were created for (`Shape`: type, geometry flags, vertex format, max vertex, index type, transform, primitive count; the counts are maxima). Creation checks `maxGeometryCount`, `maxPrimitiveCount` (BLAS, summed) and `maxInstanceCount` (TLAS) and returns `Error::OverLimit { limit, requested, max }` (`Ctx::acceleration_structure_properties()`). A BLAS is created from `BlasGeometry::Triangles` (`Triangles::new`/`indexed`, u16/u32 indices, optional transform, `opaque`) or `::Aabbs`, or sized from counts alone, `Blas::with_capacity(&BlasDesc::Triangles(&[TrianglesDesc::indexed::<V, I>(vertices, triangles)]) | Aabbs(&[AabbsDesc::new(n)]), flags)`; `VertexPosition` is sealed and names a lava `VertexFormat` (`Float32x2/x3`, `Float16x2/x4`, `Snorm16x2/x4`, the formats every device builds): `[f32; 2|3|4]`, `Vec2`, `Vec3`, `Vec4`, `Vec3A` (16-byte stride), `Half2`/`Half4` (binary16 bits, `Half4::new(Vec3)` rounds to nearest even) and `Snorm16x2`/`Snorm16x4`. A TLAS is built from `Instances`: `Instances::new` of a buffer of `Instance`s, a referencing element (its BLAS) written by `InstanceInfo::new(&blas, transform)` (`with_custom_index/with_mask/with_sbt_offset/with_flags(InstanceFlags)/with_transform`, or `with(|raw| ..)`) with `host_write_referencing` or an uploader, whose build takes the instance buffer's BLASes for the TLAS (`take_instances`; copies and compactions carry them, a deserialized TLAS counts as raw) and panics for a BLAS no build was recorded for; or `unsafe Instances::from_raw` of `RawInstance`s (`VkAccelerationStructureInstanceKHR` as plain data, public fields for the layout checks, Slang's `AccelerationStructureInstance`, which passes write), whose BLASes the caller keeps built and alive. `BuildFlags { prefer: BuildPreference::{FastTrace (default), FastBuild, None}, allow_update, allow_compaction, allow_data_access }`. `cmd.build`/`cmd.update` (refit) record one `vkCmdBuildAccelerationStructuresKHR` per call from a scratch `BufferSlice`; `cmd.build_all`/`update_all` take a `Scratch` (an aligned buffer, `Scratch::new(bytes)`/`for_any(&structures)`) and split the list into batches that fit it (panics for one that alone doesn't); a build's geometries must fit the creation's shapes (`Shape::fits`: equal but for at most its counts), an update's equal the last build's; empty lists record nothing. Built state (`BuildState`, an `Arc` shared with recordings): `is_built()` is an `AtomicBool` set when a build (or compaction, copy, deserialization into it) is recorded and reset if that recording never reaches the GPU, and the last build's shapes are applied only once it reached it (`Recording::structure_builds`, `finish_structure_builds` in `submit_inner`; updates and copies look at the recording's own builds first); traces check it (`Tlas::trace_accesses`, so generated `Accel` bindings and `BufferAccess::trace`), as do compaction and copies. Compaction: `cmd.query_compacted_sizes` into a `QueryPool<CompactedSize>` (polled on the host, never waits), `compacted(size)` (panics without `allow_compaction` or a build; never buildable, no build scratch) and `cmd.compact`, or a `Compactor<L, K>` that owns structures added with a key and drives these steps from one `record(&mut cmd)` per frame (one pool per call, sizes polled, each compaction handed back by `take_finished()` once its submission completed; failed recordings retry). Copies: `clone_target()` and `cmd.copy_structure(src, dst)` (`CLONE`). Serialization, for a BLAS disk cache: `cmd.query_serialized_sizes` (`QueryPool<SerializedSize>`), `cmd.serialize(src, slice)`, `AccelerationStructure::deserialized(&bytes)` (checks the header with `vkGetDeviceAccelerationStructureCompatibilityKHR`, `Error::Incompatible`; shapes unknown, so trace, copy and serialize only) and `cmd.deserialize(slice, &dst)`; buffer addresses of both a multiple of 256. Every structure command opens a scope and debug label (`build acceleration structures`, `compact acceleration structure`, ...), which observers see. Barriers: a structure's memory is its address range, and every structure command runs at the build stage (serialized data as `TRANSFER_WRITE`/`READ` there); a structure's `BufferAccess` names it (`structure`), so its writes mark the buffers and TLASes that reference it and a command that names a TLAS walks to its BLASes like any referencing buffer's children; a build or trace of a TLAS built from raw instances reads `EVERY_ACCELERATION_STRUCTURE` instead (`every_structure_read(stage, access)`, an empty range that only conflicts with acceleration structure writes, which the timeline tracks in `StructureAccesses`). Trace reads add `MEMORY_READ` only on Mesa's ANV (`PhysicalDevice::stale_trace_reads`, decided at init), which otherwise lets a trace after an in-submission rebuild see stale nodes. `cmd.raytrace(bindings, [w, h, d])`/`raytrace_indirect` dispatch ray tracing passes; `compute_indirect`/`raytrace_indirect` panic on an empty slice.
- Queries (`lava/src/query/`): a `QueryPool<K>` is `count` queries of one sealed kind: `Timestamp` (`cmd.write_timestamp(&pool, i, stage)`; `elapsed_ns` masks with the narrowest family's valid bits, set at the pool's creation, `instant` calibrates with `VK_KHR_calibrated_timestamps`, at most once per `CALIBRATION_PERIOD` (1 s) per pool, the best of up to four tries until the deviation, `maxDeviation` plus the host's bracket, is within `CALIBRATION_DEVIATION`), `PipelineStatistics` (flags chosen at creation, never empty (panics), `PipelineStats::get(flag)`; graphics family), `ComputeStatistics` (compute shader invocations, one `u64`, on graphics and compute families), `Occlusion` (`Draw::count_samples(&pool, i)`; `QueryPool::occlusion(count)`, or exact counts with `precise_occlusion(count)` and `precise-occlusion`), `SerializedSize` (`query_serialized_sizes`), `Performance` (hardware counters from `query::counters()`, each with its `CounterUnit` and `CounterScope`: at most `MAX_COUNTERS`, lava's own cap so a query's values fit an array; graphics family; the pool holds the profiling lock until it is destroyed) and `CompactedSize`. Which kinds a family records is a type: `RecordedOn<Q>` (timestamps everywhere, occlusion, pipeline statistics and counters on `HasGraphics`, compute statistics on `HasCompute`) bounds `cmd.query` and `QueryRecorder::begin_query`/`end_query`, so the others don't compile (compile_fail doc tests on `RecordedOn`). `cmd.query(&pool, i, |cmd| ..)` wraps commands in a statistics, occlusion or performance query, one active per kind: the recording keeps the active pool and index per kind (`Recording::open_queries`), `end_query` panics unless they match, and a recording that ends with one active fails (replayed, then panics). A pool holds one recording: the first command of a recording that touches it resets it on the host and panics if the submission that recorded into it before (its timeline and value) hasn't completed, so keep one per frame slot; every timestamp, query and compacted size takes its indices through `QueryPool::take` (checked against the pool, `checked_add`), which sets a used bit per query, cleared at that reset, and panics on a second use in one recording. Counters follow their scope: `CounterScope::CommandBuffer` ones only around a whole recording, `submission.submit_profiled(&pool, i, |cmd| ..)` (begins the query as the recording's first command, before the heap binds, and ends it as its last, after the final barrier; observers see it as active), `RenderPass` ones never inside a rendering, `Command` ones anywhere; one counter pool per recording (no `performanceCounterMultipleQueryPools`). `counters::passes(selection)` and `counters::fits(selection)` (one pass, at most `MAX_COUNTERS`) say whether a selection records like any query; one of more passes only through `timeline.capture(&pool, i, |cmd| ..)` (graphics), a tool capture that records the closure once per pass, each a profiled submission with `VkPerformanceQuerySubmitInfoKHR::counterPassIndex`, blocking after each, without resetting the pool after the first pass (`Profile::pass`), so the recordings should be alike and present nothing. Pools are created reset, `read(first, &mut out)` never waits (false until the recording finished) and panics outside the pool, and the recordings that use one keep it (its `VkQueryPool` is a `PoolOwner` in an `Arc`), so a dropped pool lives until they completed. Scope observers (`query/observer.rs`) are lava's hook into recordings, like a tracing subscriber's `on_enter`/`on_exit`: `cmd.measure(Some(&mut observer), name, f)` attaches a `ScopeObserver<K>` (`K` the recording's queue kind, `Graphics` by default) while `f` records, and it sees the root `name`, every `cmd.scope(name, f)` (also a debug label; there is no unbalanced begin/end) and every pass and rendering (`ScopeInfo { name, depth, pass }`, the name borrowed for the hook's call: scope and rendering names are any `&str`, labelled through a stack buffer), each entered and exited once in nesting order, never inside a rendering. Its hooks get a `QueryRecorder<K>`, which can only write timestamps and begin and end queries of the kinds `K` records (`is_active::<Q>()` says whether one of that kind is open, e.g. a `cmd.query` around the scope), so what `on_enter` records comes before the scope's commands, but after a pass's or rendering's barriers (its scope, debug label and timestamps leave them out), and what `on_exit` records after them. `measure` holds the observer as a lifetime-erased pointer to a `Typed<K>` wrapper (`observer::Observer`, the queue kind erased for the untyped `Recording`) and clears it also when `f` panics (`catch_unwind`, then `resume_unwind`). Timelines know nothing about queries besides `submit_profiled` and `capture`.
- Public surface: the common types are re-exported at the crate root (`lava::Buffer`, `BufferSlice`, `Image`, `ImageView`, `ImageSlice`, `CommandBuffer`, `Timeline`, `Wait`, `Ctx`, `Blas`/`Tlas`, `lava::acceleration_structure`, ...) and, with the view and memory traits, `usage!` and the `glam`/`bytemuck` modules, in `lava::prelude`; `error`, `object`, `state`, `vkobjects` and the `slice` modules are private, internals (`Functions`, `PhysicalDevice`, `RawImage` in a private module, the ray tracing pipeline types, `CallsiteGuard`) crate-private, and the `Views` methods `#[doc(hidden)]`. lava-build-slang's `compile` and `describe` are private (stages are `compile::Stage`), its `hot_reload` `#[doc(hidden)]` (what `watch!` expands to).
- `lava-tests` (`publish = false`): lava's GPU tests as an ordinary lava user, with their own passes (see Tests).
- The engine (`../GameEngine`, its own `CLAUDE.md`) is lava's main user: `core/build.rs` compiles its passes with lava-build-slang, `core` records them. Check that it still builds after changing lava's API.

## Optional features
- Every optional device feature is two cargo features of lava (`features!` in `features.rs`; the field of `Features` is the name with `_`, the type in `features::gate` its PascalCase): `X` compiles it and lava checks the device where it is used, `assert-X` (implies `X`) makes `init` refuse devices without it and drops the checks, neither compiles its API out (`#[cfg(feature = "X")]` on modules, types, fields and functions; internal code that runs either way asks `<gate::X as On>::on()`). `default` is every `X`; the engine turns defaults off and lists its own (`../GameEngine/core/Cargo.toml`), and so must every crate between (lava-build-slang's hot-reload dependency and lava-tests take lava without defaults).
- A function that only fails on the missing feature returns `Gated<gate::X, T>` (`T` when asserted, `Result<T, MissingFeature>` when checked; `features::gated::<F, _>(|| ..)` builds it, pairs `(A, B)` gate on both). One that fails otherwise too returns `lava::Result` and calls `gate::X::check()?` (`Error::MissingFeature`). Loaders of optional extensions are `Loader<gate::X, T>` in `Functions` (`T` when asserted, `Option<T>` when checked, read with `loaded`, only past a check). Objects that exist only past a check (a `Blas`, a host-copy image, a performance pool) need no check in their commands.
- Passes: lava-build-slang reads each pass's `OpCapability`s (`lava-build-slang/src/features.rs`, a copy of `features::SPIRV_CAPABILITIES`; its test compares them; both scans stop at the first instruction after the capabilities and extensions, lava's in place, `features::spirv_capabilities`, once per pass at init) and gates the generated `push_bindings` by them, so recording stays infallible; without the cargo feature the bindings don't compile (`#[diagnostic::on_unimplemented]` on `Feature` names it). `init` refuses a pass map with a pass whose feature lava was compiled without, and `PipelineManager` still panics when hand-made bindings of a pass the device can't run are recorded. Features map Vulkan bits one to one except where a capability allows less: `shader-int64-atomics` also enables `shaderSharedInt64Atomics`, `shader-clock` `shaderDeviceClock`, and `ray-traversal-primitive-culling` (`RayTraversalPrimitiveCullingKHR`, which ray queries imply) `rayTraversalPrimitiveCulling`, each only where the device has it (`FeatureChain::enabling` gets the queried chain); `clip-distance`, `cull-distance` and `storage-input-output-16` are their core bits; `shader-output-layer` (`ShaderLayer`, `ShaderViewportIndexLayerEXT`) is `shaderOutputLayer` with `shaderOutputViewportIndex`, `dual-src-blend` `dualSrcBlend`, `multi-draw` `VK_EXT_multi_draw`.
- `present-fences`, `hdr-metadata` and `fifo-latest-ready` exist only with a display (init clears them without one, and their `assert-` features require them only with one); `present-fences` also needs the instance extensions `VK_KHR_get_surface_capabilities2` and `VK_EXT_surface_maintenance1`, and windows need it (`PresentSurface::new`).
- `async-compute` and `async-transfer` are queue families, not Vulkan features: the device has them when it has a family with compute but no graphics, or transfer alone (`DeviceFacts`, `pick_queue_families`); lava creates their queues only where they are on, and `Timeline<Compute>`/`Timeline<Transfer>` return `MissingFeature` elsewhere.
- Formats and memory: `bc-compression`, `etc2-compression` (ETC2 and EAC) and `astc-compression` (ASTC LDR) are `textureCompression*` and compile their format types (`format::compression` names a format's; `Image` creation returns `MissingFeature` without it); `sparse-binding` (`sparseBinding` and a graphics family with `QUEUE_SPARSE_BINDING`) with `sparse-residency-buffer`, `-image-2d` and `-image-3d` on top (the types are `#[cfg]`'d by the residency features); `external-memory` is `VK_KHR_external_memory_fd` on Unix, enabling `VK_EXT_external_memory_dma_buf` where the device has it (`Ctx::dma_buf`, `HandleType::supported`).
- `Config::disabled` leaves features off on a device that has them (with what needs them, `Features::consistent`); `lava-tests/tests/gpu_missing_features.rs` uses it to test the `MissingFeature` paths and the baked draw state.
- Extended dynamic state stopped being mandatory on 2026-10-17 after vulkan.gpuinfo.org's coverage (Windows: extended dynamic state 3 72%, its conservative raster bit 56%, depth clamp control 53%, `rectangularLines` 56%; `VK_KHR_device_address_commands`, still mandatory, 15%; `VK_EXT_descriptor_heap`, mandatory since 2026-10-19, is in Mesa 26.2 and NVIDIA 610): `dynamic-*` features decide it, lava sets no sample locations, MSAA or alpha-to-one state, and `VK_EXT_color_write_enable` is gone.

## Lifecycle and errors
- Lava's globals (`Ctx`, `Functions`, `Bindless`, the `PipelineManager`, counters) are `global::Global`s: an `AtomicPtr` set by `init` and taken by `shutdown`, one load per read. What makes taking them sound (`global.rs` docs): every lava object (buffer, image, acceleration structure, structure arena, query pool, sampler, slot range, surface, timeline, uploader) holds a `global::Live` count as its last field, from before its constructor touches lava until its drop finished, and every public free function that touches lava's state takes one for its call (`state::call()`); lava's own buffers (heaps, binding tables) hold uncounted ones. `shutdown` closes the count only when it is zero (one CAS), else returns `Error::ObjectsAlive { count }` and destroys nothing; `init` and `shutdown` hold `global::LIFECYCLE`. The `Ctx` box is leaked at shutdown, not freed, so getters that take no count (`Ctx::features()`, `device_properties()`, the feature checks) read valid memory while it runs; afterwards every call panics with `global::NOT_INITIALISED`. Counters of `query::counters()` are leaked too (`&'static`), and `QueryPool::performance` refuses those of an earlier context.
- `lava::shutdown()` (`#[validation_trace]`): device idle (a lost device is fine), what every timeline kept (`timeline::release_all`, before the live count is checked), `pipeline::save_cache_now`, pipelines and modules and cache (`pipeline::destroy`), the heaps (`Bindless::destroy`), what that kept, the timeline semaphores (`timeline::destroy`; values go on in the next context, whose semaphores start at the index's last submitted value, so old `Wait`s are done), the counters, the pass map, then the allocator, device, debug messenger and instance (`Ctx::destroy`). A failed `init` runs the same `teardown` for what it made after `Ctx::init` (whose own steps undo themselves), after pure checks that need no device (`Config::disabled` naming asserted features panics; `pipeline::check_compiled`).
- Errors (`error.rs` docs): programmer errors panic (host copies of a wrong mip, region or length, `Uploader::image` likewise, sampler anisotropy out of range, performance pools of 0 queries or a bad counter count); device and environment failures are typed `#[non_exhaustive]` `Error`s: `DeviceLost`, `OutOfMemory` (Vulkan and gpu-allocator), `SurfaceOutOfDate`, `SurfaceLost`, `NoSuitableGpu { rejected }`, `Unsupported(String)`, `MissingFeature`, `OutOfBindlessSlots { heap: bindless::Heap, count }`, `OutOfTimelines`, `SliceOutOfRange`, `StagingFull`, `ObjectsAlive`, `Vulkan(vk::Result)` for the rest, `Loading`/`Allocation`/`Io` wrappers, and `Other { message, source }` only where nothing else fits (`Error::other`, and `err.context(..)`, which leaves the typed variants unwrapped). `Display` is the error's own text; only `Other` has a `source()`. No `From<String>`.
- Validation messages are `tracing` events of target `vulkan-validation` (error, warn, debug, trace by severity) with `message`, `typ` and `flags` (raw `VkDebugUtilsMessage{Type,Severity}FlagsEXT` integers, which the engine's console reads) and `validation_location`; shader printf is `info` at `lava::state`. The messenger asks for errors and only those other severities `tracing` enables at init (a subscriber installed later misses them), and the callback formats inside the event macros, so filtered messages cost nothing. `Buffer`/`Image`/`AccelerationStructure::named(name)` names the allocation (gpu-allocator's `rename_allocation`) and, with debug utils loaded (validation on), the Vulkan object.

## Images, formats and transfers
- Formats (`image/format.rs`): one marker type per format in `formats!` tables (`plain_info`, and per compression feature `bc_info`, `etc2_info`, `astc_info`), whose `Info` (aspects, texel size, shader texels, clear variant, `Numeric`) `format::info` finds for `Dynamic` and the checks; `known()` (what `PresentSurface::new`'s fallback picks) is "has a table entry". `format::block` gives every compressed format's `Block` (BC, ETC2 and EAC 4x4 of 8 or 16 bytes, ASTC NxM of 16), `copy_block` the block a copy of one aspect moves (a combined format's depth or stencil texel alone), and every size check goes through it (`slice::rows_len`: up to the last block's end, with row length and image height): host copies, buffer-image copies (the size, the address a multiple of the block, 4 for depth and stencil, whole-block boxes) and `Uploader::image` (which also refuses blocks that don't divide the ring's 16-byte alignment); a format without a block refuses the copy. 64-bit clear components take two words each (`pack_64`), so a `VkClearColorValue` holds two; a third or fourth non-zero one panics.
- `Ctx::format_properties(format)` caches `VkFormatProperties3` (optimal, linear, buffer features; `format_features` is the optimal ones) per format, one lock and lookup; `Ctx::image_format_limits` caches `vkGetPhysicalDeviceImageFormatProperties2` per description (format, type, usage, create flags, external handle type). Every image creation (`RawImage::create`, behind `Image::with_params`, sparse and external images) asks it and returns `Error::Unsupported` for a description the device can't make or limits it exceeds, and for host-copy usages without `HOST_IMAGE_TRANSFER`.
- Commands check formats (panics): blits `BLIT_SRC`/`BLIT_DST`, a linear filter `SAMPLED_IMAGE_FILTER_LINEAR` and no integer source, integers only into integers of their signedness (`Numeric`), no overlapping boxes of one mip of one image; `clear_image` no compressed formats and `TRANSFER_DST`; `clear_depth_stencil` (graphics, `vkCmdClearDepthStencilImage`, every aspect, depth in 0 to 1); `copy_image(src, dst)` (`vkCmdCopyImage2`, any family and dimension, equal extents and layer counts, the same `Block`, depth and stencil formats only into themselves, every aspect, no overlap, `TRANSFER_SRC`/`DST`). Buffer copies take `impl Into<TexelBuffer>`: a `BufferSlice` (tightly packed) or `slice.rows(row_length, image_height)` (in texels, 0 or at least the box, whole blocks); host copies have `copy_rows_from` and check whole blocks like GPU copies. Copies and blits track only the mip they address (`ImageSlice::level`, `mip_access`): all of a `Single` image's mips, which share one state.
- `MutableFormat` in a usage creates the image with `MUTABLE_FORMAT | EXTENDED_USAGE` (`ImageUsage::create_flags`, kept in `RawImage::create_flags` through `erase`; a `Dynamic` usage never creates one): `view.reinterpret::<F2>()`/`reinterpret_as(format)` (`U: IsMutableFormat`) is a view of the same mips and layers in another format of the image's compatibility class (`format::class`: uncompressed colour formats by texel size, `A8Unorm` alone, compressed ones per block type, depth and stencil formats alone; panics otherwise), without a handle (`view.bind::<K>()` binds it) and, for attachments, with its own `VkImageView` from the image's `ViewCache` (keyed by format too). Descriptor writes chain a `VkImageViewUsageCreateInfo` of the descriptor's own usage and lava's `VkImageView`s one of the image's attachment usages, so an sRGB image with storage usage is valid (storage through a UNORM view; Intel has no sRGB storage).
- `Image::fit(extent) -> Result<bool>` recreates an image at a new extent (same format, usage, mips, layers and create flags) bound with the same `bind_*` kinds at new slots, so its handles change: frames in flight read the old image, which whatever still holds it (submissions, referencing buffers) keeps; rewrite the references to it.
- Sparse resources (`sparse.rs`): `SparseBuffer<T>` (its own `VkBuffer`, slices with `sparse: true`, which drops `FULLY_BOUND` from their address flags) and `SparseImage<F, U, D>` (a colour, one-layer `Image` created with the sparse flags and no memory, which it derefs to; `granularity()`, `mip_tail()`, `page_size()`) keep their resident pages (`Pages`, one gpu-allocator allocation per page or tile, and one for the mip tail) and free them after the resource. `timeline.bind_sparse(&[SparseBind::buffer/image/mip_tail(.., resident)])` (`Timeline<Graphics>`) allocates and binds or unbinds them in one `vkQueueBindSparse` that waits for the timeline's last value and signals its next (`Timeline::submit_sparse`); the next submission waits for it (`Inner::sparse_wait`), since binds aren't ordered with command buffers; unbound pages are retired.
- External memory (`external.rs`, `cfg(unix)`): `ExternalBuffer<T>` (opaque fd or dma-buf) and `ExternalImage<F, U, D>` (opaque fd) own a dedicated `VkDeviceMemory` from `VkExportMemoryAllocateInfo` or `VkImportMemoryFdInfoKHR` (the first device-local type of the requirements, as every exporter and importer of one description picks), deref to their `Buffer`/`Image` (null gpu-allocator allocation, `Buffer::from_external`, `Image::from_raw`) and free the memory after it; `export()` returns an `OwnedFd`, `import(fd, ..)` takes one. An imported image starts undefined: lava records no layout handoff (`QUEUE_FAMILY_EXTERNAL`). No Win32 handles.

## Bindless slots
- Descriptors live in two heaps of `VK_EXT_descriptor_heap` (`bindless.rs`), mapped `CpuToGpu` buffers with `DESCRIPTOR_HEAP` usage that every command buffer of a graphics or compute family binds once (`Bindless::bind`): the resource heap holds the image descriptors (`HeapLayout`: `count` slots, min(`MAX_IMAGE_SLOTS` = 2^16, what `maxResourceHeapSize` holds), then the implementation's reserved range), the sampler heap the samplers (at most `MAX_SAMPLERS` = 4096). Shaders index both directly (`ResourceDescriptorHeap[slot]`/`SamplerDescriptorHeap[slot]` in `bindless.slang`, `SPV_EXT_descriptor_heap` through the `spvDescriptorHeapEXT` capability of `compile::session`), so pipelines have no layout and no mappings, a heap index needs no `NonUniformResourceIndex` (heap accesses are non-uniform unless declared otherwise), and lava's slot stride must be the shader's (`OpConstantSizeOfEXT` of the descriptor type: its size aligned to its alignment, `HeapLayout::new`). Descriptors are written with `vkWriteResourceDescriptorsEXT` from a `VkImageViewCreateInfo` (`ShaderImage`, layout `GENERAL`, the depth aspect of a combined depth-stencil format) straight into the mapping; no `VkImageView` exists for them.
- An image handle is one `u32`, `ImageHandle<K>` (`#[repr(transparent)]`, `AnyBitPattern` but not `NoUninit`: only reference infos write handles into buffers, `ImageReference` for a buffer of bare handles; generated push constants implement `NoUninit` themselves): bits 0–29 the slot of its first descriptor, bit 30 that descriptor's kind (0 sampled, 1 storage), bit 31 its width (0 one descriptor, 1 two: sampled at the slot, storage at the next); `ImageHandle::NULL` is 0, and slot 0 of both heaps is reserved (sampler slot 0 holds lava's default sampler, `SamplerHandle::DEFAULT`). `K` is a sealed kind: `Sampled`, `Storage`, `Combined` (the typed kinds, `Allocatable` with their `WIDTH`), or `Dynamic` (the default, from `erase()`, for `DynImg`); `as_sampled()`/`as_storage()` (`HasSampled`/`HasStorage`) and `erase()` only retype the bits, and `sampled_slot()`/`storage_slot()` decode them, as `bindless.slang` does. Mips of a chain lie `width` slots apart (`handle.mip(level)`, `Img.Mip(level)`).
- Lava allocates the slots (one `Mutex<Ranges>` of sorted, coalesced free ranges, first fit). `Image::new`/`with_mip_levels`/`with_params` make an unbound image (null handle); `bind_sampled()`/`bind_storage()`/`bind_combined()` (`where Self: SampledImage`/`StorageImage`/both) take one or two free slots, `bind_mips_sampled/storage/combined()` one block of `mip_levels * WIDTH` (mip `i` at `first + i * WIDTH`), write right away (no submission reaches a fresh slot) and return `Result<Self>` (`Error::OutOfBindlessSlots`), e.g. `Image::new(extent)?.bind_combined()?`; a view is bound once, so a second bind panics. `ImageView::bind::<K>()` binds any other view (a layer, some mips or layers, a reinterpreted format) at slots the image owns, once (its handle is kept in the image's `ViewCache`, so `handle::<K>()` finds it on views made again). `Image::handle::<K>()`/`ImageView::handle::<K>()` return the handle as `K` and panic, naming the bind to call, unless the binding has `K`'s descriptors (a `Combined` binding serves all three); `dynamic_handle()` is whatever a view has, for a `DynImg`. The slots are free again once the image is destroyed (Lifetimes). There are no reserved slot ranges: what the GPU reads by index it reaches through a referencing buffer. A `PresentSurface` binds each swapchain image with every descriptor its usage allows (`Combined`, `Sampled` or `Storage`; a recreated swapchain at other slots; the old one frees its slots when it is destroyed).
- Samplers are runtime objects: `Sampler::new(&SamplerDesc)` (a const builder: `SamplerDesc::new()`/`Default` is trilinear and repeating; `filter`, `address_mode`, `border_color`, `compare(op)` for `SampleCmp`, `reduction(mode)` with `sampler-minmax`, `max_anisotropy(ratio)` with `sampler-anisotropy`, checked against `maxSamplerAnisotropy`) writes a free slot of the sampler heap with `vkWriteSamplerDescriptorsEXT`, `handle()` is the `SamplerHandle` shaders take as a `Sampler`, and dropping it frees the slot once retired. Equal descriptions get separate slots.

## Shader pipeline
- `core/build.rs` calls `lava_build_slang::Shaders::new().passes(dir).include(dir).define(name, value).compile()` (`#[must_use]`; `.optimization(..)` and `.debug_info(bool)`, Slang's debug info for RenderDoc and Nsight, exist too; core calls neither) (paths relative to the package, canonicalised). Every `*.slang` file of a pass directory (not recursive) is a pass named after its stem (`bvh_cull` → `BvhCull`, refused unless it makes a Rust identifier; two files of one name are refused naming both), and a file of several compute entry points one pass per entry point, linked alone, named stem + entry (`fill` of `test_multi.slang` → `TestMultiFill`), in declaration order. lava-build-slang compiles the files with `shader-slang` on up to 4 threads (a global session and session per thread, results in file order; `codegen::compile_all`, `MAX_THREADS`: more threads cost more than they gain), each through `compile::compile_file` (which its hot reload shares, so both compile alike) into `describe::PassDesc`s, plain data read from the reflection (`describe.rs`: kind, entry points with workgroup and wave sizes, push constants and specialization constants as `Ty` trees with lava's handle types, `[RustConst]` exports, `layout_hash`), writes SPIR-V to `$OUT_DIR/lava/passes/`, and **generates `$OUT_DIR/lava/bindings.rs`** from them (`codegen.rs`), rewritten only when it changed. Errors don't stop at the first pass: every file's (Slang's, and lava-build-slang's with the field path, `push constant `nodes.next``) are listed in one panic; Slang's warnings become `cargo::warning=` lines (its "profile implicitly upgraded", 41012, is off: lava reads capabilities from the SPIR-V). `core/src/bindings.rs` includes it with `lava::include_passes!()`, so the passes are `crate::bindings::*` in core, and `crate::bindings::PASS_MAP` (every `PassEntry`: name, SPIR-V always embedded with `include_bytes!`, `PassKind` (from the entry points' stages: vertex or mesh (with task) raster passes with or without a fragment shader, compute with its `[WaveSize]` as `subgroup_size`, ray tracing) with its entry points as `&'static CStr` (`c".."` literals), constant map entries and `constants_size`; a pass's index is its position in the map, which its bindings name) goes to `lava::init`, which lava can't include itself since it is compiled before the application's build script runs. The generated code names everything by absolute paths (`::lava::..`, `::lava::glam::..`, `::lava::bytemuck::..`, which lava re-exports, bytemuck with `derive` and `min_const_generics` for arrays of any length; derives carry `#[bytemuck(crate = "::lava::bytemuck")]`), imports nothing into its includer, and uses only lava's public API (`Bindings::new`/`with_constants`, `unsafe` with the generator contract in their `# Safety` docs: the pass index and its kind marker, its push constant struct, the accesses its fields make, its constants' `constants_size` bytes; the generated calls sit in `unsafe` blocks with a `// SAFETY:` comment, and debug builds check the kind (`kind::Kind`) and constant size once lava is initialised; `BufferSlice::access`/`address`, `ImageView::access`, `ImageRef::view`, `Tlas::trace_accesses`, `kind::*::STAGES`: the API for other binding generators, e.g. GLSL). Per pass `P` it generates the GPU struct `CPBindings` (private zeroed `_pad` fields for Slang's gaps, tail included; none for a pass without push constants, which pushes `()`), the argument struct `PArgs` (every push constant by name: buffers as `BufferSlice<'a, T>`, images as a generic view parameter per field (`TargetView`), `Accel` as `&'a Tlas`, plain values as their GPU type; `PArgs {}` without push constants), with specialization constants `PConstants` (the same, `SCONST` handles as views, slices and `&Tlas`) and the packed `CPConstants`, and `P::push_bindings(args, [constants,] accesses)` (`#[track_caller]`, checks first: `ImageRef::view`, `texel_check`, `usage_check`, `handle::<K>()`, all `#[track_caller]`), gated by the pass's capabilities; compute passes get `P::WORKGROUP_SIZE: [u32; 3]` (`[numthreads]`) and `P::groups(threads) -> [u32; 3]` (`div_ceil` per axis). For example `cmd.compute(&BvhCull::push_bindings(BvhCullArgs { nodes: nodes.range(..), count }, None), BvhCull::groups([count, 1, 1]))`, or `cmd.raster(extent, [Attachment::color(view, None)]).draw(&Draw::indexed(&RasterUi::push_bindings(args, constants, Some(Accesses::images(&textures))), indices, 1, state)).record(name)`. `[RustConst] static const` scalars (`bool`, `int`, `uint`, `int64_t`, `uint64_t`, `float`; the attribute is in `bindless.slang`) of a pass file or its `#include`s (not `import`ed modules) become `pub const NAME: T = value;`, once even if several passes include them (different values are refused). A pass's push constants are at most `MAX_PUSH_CONSTANTS_SIZE` (256, `pipeline.rs`) bytes of push data, which lava requires of the device (`maxPushDataSize`; lava-build-slang rejects a bigger struct); pipelines have no layout (`PIPELINE_CREATE_2_DESCRIPTOR_HEAP`), and shaders index the descriptor heaps directly (Bindless slots); its specialization constants have no limit. The generated return types spell out each section's size, so a binding has no inline capacity and never allocates; the pipeline arrays are sized at init from the map.
- Matrices use column-major layout (`matrix_layout_column` in lava-build-slang's `compile.rs`, shared by the build and hot reload), so a glam `Mat4` arrives untransposed and shaders write `mul(M, v)`.
- Field types map like this (`codegen::rust_ty`, the same in push constants and structs behind pointers, whose layouts differ: push constants are std430, pointees scalar, so a `float3x3` is 48 bytes in one and 36 in the other): scalars to their Rust type (`bool` → `u32`, `half` → `lava::half::F16`, the binary16 bits), vectors to glam's (`bool3` → `UVec3`, 4-byte bools; `I64Vec3`, `U64Vec2`, `DVec2`, `I16Vec2`, `U8Vec4`, ...; `half3` → `[F16; 3]`), matrices to glam's square `Mat2`/`Mat3`/`Mat4`/`DMat*` where their columns are tight, else to their columns (`[[S; column_stride]; columns]`: std430's `float3x3` is `[[f32; 4]; 3]`, `float3x4` (3 rows, 4 columns) `[[f32; 3]; 4]`, `int4x4` `[[i32; 4]; 4]`), arrays to `[T; N]` (elements padded to their stride, `[[f32; 4]; N]` for std430's `float3` arrays; other mismatches refused), and glam's SIMD-aligned `Vec4`, `Mat2` and `Mat4` only where offset and struct size are 16-byte aligned, else to arrays. Every generated struct gets zeroed `_pad` fields for Slang's gaps (tail included; `pub`, `#[doc(hidden)]` in structs behind pointers, so `Foo { a, ..Default::default() }` works anywhere) and so derives `Pod` (or `NoUninit`) without padding; a scalar-layout struct whose size isn't a multiple of its alignment (`{ uint64_t a; uint b; }`, 12 bytes) is `repr(C, packed(4))`. Structs behind pointers derive `Clone, Copy, Debug` and `Pod, Zeroable`, or, for referencing structs (see Referencing buffers), implement `Zeroable` and `AnyBitPattern` by hand (bytemuck has no `AnyBitPattern` for arrays of non-`Pod` types), get a `Default` that is zero (null handles), size and offset asserts, and every pointee a size assert against its stride; struct names carry their generic arguments (`Pair<float>` → `PairFloat`), and one name with two layouts or field types in two passes is refused naming both files (`Generator::collect`). Rust keywords as field names become raw identifiers (`r#type`). Push-constant fields: `Buf<T>` (a read-only `Ptr<T, Access.Read>`, so writing through it doesn't compile) /`MutBuf<T>` → `BufferSlice<'a, T>`, a raw pointer `T*` → a `u64` address without an access (the shader clocks' `Clocks`), and `Img` (and `ImgArray`, 2D arrays, coordinates ending with the layer) → a view `impl image::SampledView<Dim = .., Format: HasTexels<[T; N]>> + 'a` (a view of the shape's dimension and a format of the shader's texel type: `half` reads as `f32`, 8- and 16-bit integers as 32-bit ones; kinds 0 to 3, others refused; turned into `view.handle::<K>()`, which panics unless the view is bound with the descriptors the shader reads): `Tex2D` reads through the sampler (`SampledView`, `ImageHandle<Sampled>`), `Image2D`/`MutImage2D` through the storage descriptor (`StorageView`, `ImageHandle<Storage>`), and `MutTex2D`/`MutTex3D` read and sample through the sampler but write as storage (`SampledView + StorageView`, `ImageHandle<Combined>`, an image bound with `bind_combined`). A typed load of a storage image costs several times a sampler fetch on Intel (it was a quarter of the tonemap, now the composite pass), so read an image through the sampler whenever its usage allows. Behind pointers and in arrays there (`Buf<Tex2D>`, `[Img; N]`), `Img` becomes an `ImageHandle` of its kind, `DynImg` (also top-level, without accesses) an `ImageHandle` (`Dynamic`), `Buf`/`MutBuf`/`Accel` a `u64`, each a reference of its struct; `Img(handle)`/`DynImg(handle)` build them from a `uint`, and both have `IsNull()`. A `Sampler` (`bindless.slang`, one `u32`) is a `lava::bindless::SamplerHandle` anywhere, without accesses: a reference inside structs, a plain value in push constants. Sampled `Img`s have `Load(p)`, `Sample`, `SampleLevel`, `SampleGrad(sampler, uv, ddx, ddy)`, `SampleBias` (fragment shaders: implicit derivatives), `SampleCmp`/`SampleCmpLevelZero`, 2D and 3D ones `Load(p, level)`, 2D ones `Gather`/`GatherRed`/`Green`/`Blue`/`Alpha` (returning `vector<E.Element, 4>`), `uint` and `int` storage images (`MutImage*`, `MutTex*`) `InterlockedAdd`/`Min`/`Max`/`And`/`Or`/`Xor`/`Exchange`/`CompareExchange`, each returning the old texel; `DynImg` has `Sample`/`SampleLevel`; samplers have no default. `Accel` (a TLAS's address, `accel.get()` is the `RaytracingAccelerationStructure`) → `&Tlas` in push constants and `SCONST`s, a `u64` inside structs (a reference). Slang structs that mirror a lava type (`describe::MIRRORED_TYPES`: `AccelerationStructureInstance` → `RawInstance` and `Sampler` → `SamplerHandle`, whose fields are public for the checks) aren't generated, only layout-checked. `Img` and `DynImg` have `GetDimensions()`. `DynImg` (`bindless.slang`) reads the sampled descriptor if its handle has one, else the storage one (nearest), else zero (`E(E.Element(0))`); the UI pass uses it for `UIVertex.texture`; a push constant `DynImg` gets no automatic barrier: pass its image in the bindings' `Accesses`. Slang numbers fragment outputs from location 0 whatever their `SV_Target` index, so a pass that writes attachments other than the first gives them `[[vk::location(n)]]`. Every pass is its own SPIR-V module, so passes can share entry points from an include (the scene passes' `scene_mesh`). lava-build-slang rejects a pass with global parameters (descriptors, uniforms; the heaps aren't parameters), entry-point `uniform` parameters, a second push constant buffer, push-constant structs or arrays that hold handles below the top level (they would be untracked), a `MutBuf` of a referencing type anywhere a pass reaches (lava follows references only from the host's writes; raw pointers `T*` are allowed), and `[Unordered]` on anything but a write reference. The clock readout (`take`, `regions`) is generated only for `profile.slang`'s `Clock`, recognised by name and layout (`codegen::is_clock`).
- Referencing buffers (`reference.rs`, `object.rs`): a struct behind a pointer with `Buf`, `MutBuf`, image, `DynImg`, `Accel` or `Sampler` fields is a referencing type: lava-build-slang generates an `unsafe impl ReferencingData` (its `REFERENCES` in field order, nested structs and arrays flattened, at most 64; `WRITES` marks `MutBuf`/`MutImage*`/`MutTex*`, `UNORDERED` those of them marked `[Unordered]`, `bindless.slang`'s attribute for writes draws of one rendering may make in any order) and a `{Name}ReferenceInfo` taking each field as what it references (an `Option` of a view per image, generic like push constants, `None` the null handle shaders test with `IsNull()`; a `BufferSlice`; `&Tlas`; `&Sampler`; `reference::DynImage` (a view or `NULL`) per `DynImg`; an info per nested struct; arrays of them; plain fields as values), which writes the struct and its `Reference`s (`ReferenceInfo::write`). Buffers of them are written only through infos (`Buffer::host_write_referencing`, `Uploader::write_referencing`; lava's plain writes need `NoUninit`, and commands that would write one panic, `BufferSlice::access`'s guard), and the buffer keeps what they reference: `KeepAlive` (its distinct children, four compared branch-free and more through a hash index, a `u16` child index per reference, the writers and the children that reference things themselves), each child registered with its parents (`Header::parents`, `Weak`s). A GPU write or a transition away from `GENERAL` marks the written object's ancestors dirty (`mark_dirty`, a bit per timeline plus `DIRTY_LAYOUT`), and a command that names a referencing buffer walks it when it is dirty or has writers below (`walk_roots`/`walk`), turning what it reaches into accesses at every stage (`Reached`), so those get barriers and transitions back to `GENERAL` and a rendering refuses draws that write what another reaches; a write or transition of a referenced object also waits for its ancestors' pending reads (`ancestor_hazards`), since reads through a clean buffer record only the buffer's. `Buffer::reserve` and same-type copies carry the references; a buffer referencing itself keeps nothing.
- A ray tracing pass (`ray_tracing.slang` in lava-build-slang's `slang/`) has one raygen and any number of miss, hit (closest hit, any hit, intersection; procedural with an intersection shader) and callable entry points; `[Group(n)]` puts one at index n of its binding table region (the miss index, an instance's `sbt_offset`, the callable index; 0 without it, dense per region; hit entry points with the same index form one group), `[MaxRecursion(n)]` on the raygen sets the trace depth (0 to 31, 1 without it; a pass deeper than the device's `maxRayRecursionDepth` gets no pipeline and counts as missing what the device lacks, so recording it panics like a pass whose feature is missing). `compile::ray_tracing_groups` checks them, the pass table bakes them, and `layout_hash` covers them, so a hot reload that regroups is refused. Binding table records hold only handles, no shader record data.
- Specialization constants are baked into the pipeline, for values that are the same on every run (sizes, modes, device limits, a bindless handle that is fixed for the app's lifetime, like the font atlas's). Addresses in them (`SCONST` of `Buf`, `MutBuf` or `Accel`) are allowed but cost every start: an address differs from run to run, so Mesa's shader cache never hits and every start compiles the pipelines again (0.7 to 1.2 s here, against 0.1 ms cached), while the baked addresses gained nothing measurable; prefer push constants for them. Declare them with `SCONST(T, name)` (`bindless.slang`; any `Img` alias, `Buf`/`MutBuf`, which lava's test uses, and `Accel`; always a `u64` constant, an image handle zero-extended, read back through `T.fromConst`; `T` is split on commas, so a generic image needs an alias) or a plain `[SpecializationConstant] const uint name = 0;`. They become the fields of the generated `PConstants`, in id order, with the same accesses and barriers as push constants. Every pass keeps its pipelines in a map keyed by the constant bytes (laid out by `PassEntry.constants`; empty, and made at init, without constants; raster pipelines are keyed by raster state first; a key is copied to the heap only when its pipeline is made, a lookup takes the binding's bytes), so every new value builds a pipeline at first use, and a pass reaching 16 pipelines logs a warning: pass values that change on resize or per frame (frame-slot offsets, attachments, settings) as push constants.
- Compute passes with `[WaveSize(n)]` (`PassKind::Compute::subgroup_size`) are made with `VkPipelineShaderStageRequiredSubgroupSizeCreateInfo`; lava enables `subgroupSizeControl` where the device has it (`FeatureChain::subgroup_size_control`, `Ctx::subgroup_sizes()`), and a device without it, or whose `requiredSubgroupSizeStages` lack compute or whose sizes don't cover `n`, gets no pipeline for the pass, like one missing a feature (`missing_limits`).
- Pipelines (`lava/src/pipeline.rs`): per pass a `RwLock` of its shader module and one of its pipeline map (`PassPipelines`; no lock spans passes, and every lock ignores poisoning, since a creation that fails panics with no write guard held). A lookup takes the map's read lock; a miss read-locks the module, creates the pipeline outside the map's lock and inserts it under the write lock, keeping the module locked until then; if another thread inserted the key first, its pipeline is kept and the new one destroyed. `reload_pass` write-locks the module first and holds it through the rebuild, so no creation uses a module it destroys and every key is rebuilt. Every pipeline is made through one `VkPipelineCache`, loaded from `Config::pipeline_cache` at init (data of another device or driver, by its header, is ignored with a warning) and written back by `pipeline::save_cache()` (also called by `lava::shutdown`; through a `.tmp` file); init makes the unspecialised compute pipelines in one call and the ray tracing ones in another, and names every pipeline after its pass. A recording keeps its last bound compute and ray tracing pipeline (`Recording::bound_compute`/`bound_ray_tracing`): the same pass and constant bytes skip the lookup, the same pipeline the bind.
- Runtime hot reload is a debugging aid behind the `hot-reload` cargo feature of `core` and `game` (default on), which makes core depend on `lava-build-slang` with its `hot-reload` feature, so keep it simple rather than fast. The build script also writes `$OUT_DIR/lava/hot_reload.rs`, a `hot_reload::Build` (search paths, defines, optimization, debug info, watched directories, and per pass in map order its name, source, entry point and layout hash), which lava never sees. `lava_build_slang::watch!()`, which core calls right after `lava::init` (windowed and headless), includes it from the calling crate's `OUT_DIR`, checks it is the build of lava's pass map (the same names in the same order), watches its `watch_dirs` (the pass and include directories the build script was given) and lava-build-slang's `slang/`, and on any changed file there but hidden ones and editor backups (`may_change_passes`; a pass's `source` is its absolute path; any other file reloads every pass) recompiles the changed files with `compile::compile_file` in a fresh session on its own thread (a panic fails only that file, `catch_unwind`), then hands each pass's SPIR-V to `lava::pipeline::reload_pass(index, spirv) -> Result<Reload>`, which replaces the pass's module and pipelines in the `PipelineManager` (`lava/src/pipeline.rs`, the pass table types and every pass's pipeline cache) right away (`Reload::Replaced`; `Reload::Skipped` for a pass the device can't run, which has none), logging "Reloaded" only then. There is one `PipelineManager`, which hands out copies of raw `vk::Pipeline`s (a ray tracing pass's as a `BoundRayTracing`, the pipeline and its binding table's regions); a reload swaps the new pipelines into its caches and hands the old ones to `destroy_when_idle`, which destroys them once every recording in progress and submission in flight completed, so a recording that looked one up keeps using it. Without the feature nothing watches and nothing is ever replaced. Changing anything the bindings depend on (a field's name, offset or full type, specialization constants, entry points, groups, workgroup and wave sizes, exports) still needs `cargo build` so the bindings get regenerated: `BuiltPass.layout` is `PassDesc::layout_hash` (FNV-1a 64 over fixed-width values, so the same on every host) and a reload whose hash differs is refused with an error, as is one the driver rejects (nothing is replaced then); reloading rebuilds every cached specialization.

## Commands
- lava builds on stable Rust (Arch's `/usr/bin/cargo` or rustup's), edition 2024, with no `#![feature]`s; keep it that way.
- `ash` 0.38, `ash-window` 0.13 and `gpu-allocator` 0.28 come from crates.io, with no patches. ash 0.38 has headers 1.3.281, older than `VK_KHR_device_address_commands`, `VK_EXT_descriptor_heap` and `VK_EXT_depth_clamp_control`, so `lava/src/vk.rs` (`lava::vk`, the only path to ash's types: ash is a public dependency, so an ash upgrade is a breaking lava release, documented in `lib.rs` and the README) re-exports `ash::vk` and adds their structs (layouts from the registry, ash 0.38's `TaggedStructure`/`Extends*` impls so `push_next` takes them), the `VkStructureType`/`VkDynamicState` values (`vk::DYNAMIC_STATE_DEPTH_CLAMP_RANGE_EXT`) and their device functions (`vk::device_address_commands::Device`, `vk::depth_clamp_control::Device`, loaded with `get_device_proc_addr`, only the commands lava records; a missing one panics naming it). Lava code uses `crate::vk`, never `ash::vk`. Add a newer extension there the same way, and delete the additions once an ash release has them. ash 0.38's `push_next` links the pushed struct's whole `p_next` chain, so a struct reused from an earlier chain must be unlinked first (`FeatureChain::chain` does). `shader-slang` and `shader-slang-sys` are slang-rs's crates.io release 0.1.0. Its reflection wrappers turn some null results of Slang's C API into references (undefined behaviour; slang-rs fixed it on main after the release), so lava-build-slang reads reflection only through `lava-build-slang/src/reflect.rs`: `checked_*` methods returning `Option`s that call the C API (`shader-slang-sys`, a direct dependency for this) where 0.1.0 doesn't check. Never call 0.1.0's `name`, `type_layout`, `category` (it goes through `type_layout`; use `checked_category`), `element_type_layout`, `function`, `fields`, `parameters`, `entry_points`, `user_attributes`, `type_parameters`, `value_parameters`, `concrete_type`, `Variable::ty`, `Decl::name` or `Decl::as_variable` there. 0.1.0 also drops Slang's diagnostics on success, so `reflect::load_module`, `link` and `target_code` call the COM vtables (`sys::ISessionVtable`, `IComponentTypeVtable`) themselves and return the warnings. Generic type parameters are `Variable`s (0.1.0 mistypes them). Delete `reflect.rs` once slang-rs releases its fixed API. lava had its own forks of all four until 2026-10-16 and went back to upstream by choice.
- The Slang SDK lives in `slang-sdk/` (gitignored; the engine's `.cargo/config.toml` points at it too). Linking goes through `.cargo/config.toml`: `SLANG_DIR` for slang-rs's build script (bindgen, so it needs clang) and an absolute rpath to `slang-sdk/lib` for build scripts and hot-reload binaries, the setup lava-build-slang's README asks of every user. lava-build-slang's `build.rs` links `slang-compiler` explicitly because `-lslang` would pick up the unrelated S-Lang library.

- **Publishing** (nothing is published yet): `lava-macros`, `lava`, `lava-build-slang`, in that order; every dependency is on crates.io. Until `lava-macros` is published, `cargo package` can only verify it; `lava` and `lava-build-slang` need `--no-verify`/`--list`. The package name `lava` is taken by an abandoned crate whose owner was asked for it.
